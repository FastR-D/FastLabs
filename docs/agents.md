# Agent 定义与任务协作

## 四个概念

| 概念 | 含义 | 生命周期 |
| --- | --- | --- |
| Agent 定义 | 名称、职责、指令、Skills 文本、角色与默认执行配置 | 用户保存、版本更新、归档 |
| 执行实例 | 某个任务中的规划者、子任务执行者或验收者 | 绑定任务，持有配置快照 |
| CLI 会话 | Provider 的上下文与对话历史 | 新工作新建；保留现场时可续接 |
| 单次运行 | 一次排队和 CLI 调用 | 保存状态、会话、配置、时间及退出信息 |

定义与实例不是继承层次；多个实例可以来自同一定义，并拥有互不混用的会话。
任务保存目标、依赖、验收与交付，仍是工作组织单位。运行成功只表示调用成功，
不等同于任务验收通过或代码已交付。

## 使用流程

1. 在侧栏“Agent 库”创建定义，填写职责、指令、Skills，选择角色和执行器。
2. 创建任务时选择规划、默认执行、验收 Agent；不选择时使用初始化的角色定义。
3. Planner 从创建任务时的 Agent 目录快照中选择已有定义，或提出任务内临时定义。
4. 在确认页选择 Agent，或编辑任务内定义；临时定义可以另存到库。保存不启动执行。
5. 确认执行后，平台按依赖启动 CLI、集成提交、验收和交付。简单目标可只有一个执行者。
6. 在任务详情查看每次调用历史；未清理现场时可以继续原会话。交付清理后用“继续修改”创建新任务。

每次编辑定义产生新版本，已有任务保留原快照。归档只阻止新的选择，不破坏历史任务。
初始规划、执行、验收定义继承现有用户设置；旧设置页修改默认执行器时会同步更新对应初始定义。
若默认定义已归档，未明确选择 Agent 的新任务回退到角色执行器设置。

手动修改任务执行器或模型属于该实例的运行覆盖：仍保留定义来源和指令，运行记录保存实际执行配置。
更换执行器采用新会话；原会话续接不重新注入定义，也不允许更换执行器。

## 第一版边界

- Skills 是随快照保存并注入提示词的内容，不安装插件或任意工具。
- Agent 定义不能授予权限、修改沙箱、读取其他租户凭证或提升并发上限。
- 由 FastLab 调度执行实例，不开启 CLI 内部递归派发；规划后需用户确认。
- 没有常驻 Agent 进程、跨任务自动记忆或自动发布会话；agent-git 暂缓集成。
- 原有用户 orchestration Skill 不覆盖；若旧规则禁止能力定义，可在设置中编辑或恢复当前模板。
