# 需求文档

## 目标与范围

FastLab 为 FastResearch 的可信内部成员提供一个可审计的 Agent 任务工作台。用户提交目标，
检查 Planner 生成的计划，再由 Codex 或 Claude 在隔离 Worktree 中执行；FastLab 负责依赖、
并发、Git 合并、验收和最终交付。

本阶段增加租户独立的 Agent 定义库、版本快照、任务内临时定义和调用历史；
沿用任务分发 Skill、CLI/API Key 认证和托管工作空间。不修改 FastResearch 或 FastNews，也不
恢复已移除的飞书功能。实现进度和发布验证状态以根目录 `plan.md` 为准。

## 角色

- **内部用户**：通过 FastResearch 登录，在自己的大工作目录中创建或克隆托管仓库；选择 Planner 与
  Worker 的 Agent/模型，维护自己的分发 Skill，并选择独立 CLI 登录态或加密保存的个人
  Provider API Key；提交、审批、停止、重试、验收和交付任务。
- **管理员**：安装并固定 CLI 版本，管理 FastLab 配置、租户仓库、备份、容量、安全门禁和
  发布回滚；管理员不能从网页切换执行后端。
- **维护者**：在不破坏外部契约的前提下扩展 Runner、Agent、路由和状态，并维护契约测试与
  迁移说明。

## 核心用例

1. 用户从 FastResearch 同域入口 `/lab/` 打开 FastLab，并复用当前成员会话。
2. 用户在“仓库管理”中创建空仓库或从 HTTPS Git URL 克隆；FastLab 自动在本租户大工作目录
   `repositories/` 下分配目录，用户不填写服务器路径。
3. 用户点击“设置”后在同一单页应用内进入独立设置中心，通过“← 返回”回到来源页；左侧分类
   导航分别进入 Agent 配置、模型凭证、Skill 配置和仓库管理，右侧一次只显示当前分类。
4. 用户在设置中心选择 Planner Agent/模型、Worker 默认 Agent/模型、认证来源，并可编辑自己的
   orchestration Skill。
5. 用户提交目标和限制；Planner 按任务创建时的设置与 Skill 快照只读分析并生成可编辑计划。
6. 用户确认计划后，多个子任务按依赖与并发限制在独立 Worktree 中运行。
7. FastLab 提交并顺序合并子任务，执行最终验收，再安全快进目标分支。
8. 用户可以停止、重试、续接会话、修改并重跑、重新验收、再次交付或清理现场。
9. 管理员可以备份、恢复、监控队列并在不修改数据格式的情况下回滚代码。

## 功能不变量

- 页面、HTTP 路由、JSON 字段、状态语义、SQLite 表、任务文档和 Git 行为保持兼容；有意变更
  必须先更新契约、测试和迁移说明。
- 设置中心必须在当前单页应用内切换；桌面端采用左侧分类导航，窄屏采用横向分类页签，右侧
  只渲染当前分类。返回应恢复进入设置前的页面，离开有未保存内容的表单前必须确认。
- Planner 只读使用当前租户登记的 Git 工作树，Worker/Verifier 只使用 FastLab 为当前任务生成的
  Worktree；路径解析不能越出当前租户的 `repositories/` 或 `worktrees/`。
- 多用户模式的仓库路径由 FastLab 生成并只在服务端保存。用户界面和创建 API 不接受绝对路径
  或租户内相对路径；仓库记录仍作为任务选择、默认值和所有权边界。
- Planner、Worker、Verifier、重试和续接都占用同一全局 Agent 配额。
- 4U8G 默认全局并发为 4、每用户为 1；等待者进入全局 FIFO 队列。任务自身并发上限不能
  绕过这两个限制。
- 用户 API Key 加密保存，API 只返回掩码；只在用户选择 API Key 认证时向子进程注入当前
  Provider 的密钥。CLI 模式使用当前用户独立 runtime，不因 API Key 为空而禁用执行器，也
  不得共享宿主或其他用户的 CLI 登录态。新用户默认选择 Codex CLI。
- 每个用户的 Planner/Worker 默认值和分发 Skill 相互隔离。创建任务时保存实际设置与 Skill
  摘要，之后修改个人设置不能悄悄改变已有任务。
- 所有可编辑模型字段使用当前 Agent 的服务器允许列表作为严格选项，并提供空值“CLI 默认模型”；
  切换 Agent 必须刷新选项，历史任务中的旧模型可以只读兼容，但不能任意提交新模型名。
- 取消、超时和服务停机必须终止对应完整进程树，晚到的旧 Dispatch 不能覆盖当前状态。
- 目标目录有未提交改动、分支改变、历史改写、同步冲突或验收失败时，不得覆盖用户文件。
- SQLite 文件名和租户布局保持兼容；Agent 库采用新增表与版本标记的增量迁移，先备份再升级。
- `/api/health` 可匿名访问；其他页面/API 在 `research` 模式下必须通过 FastResearch 会话。
- 不恢复飞书入口，不修改 FastResearch 和 FastNews 源码。

## 非功能要求

- **容量**：约 50 名用户可以同时登录、浏览和提交；4U8G 同时运行最多 4 个 Agent。
- **响应性**：排队和 Agent 执行不得阻塞 HTTP 控制面；浏览、停止和健康检查仍可响应。
- **可靠性**：异常退出后，遗留运行状态转换为需要处理，不自动重复执行 Agent。
- **可恢复性**：每日及发布前备份，RPO 24 小时、RTO 4 小时；季度执行恢复演练。
- **可观测性**：健康、队列、活跃运行、任务事件和 systemd 日志可用于定位故障，日志不得
  暴露完整密钥。
- **可移植性**：Python 3.10 和 3.13 通过测试；前端不引入构建链，Node 22 只用于测试。
- **可维护性**：启动入口保持精简，统一从包导入，业务实现按模块边界组合；新扩展必须有相应测试和文档。
- **安全性**：直连模式必须严格启用 CLI 沙箱并失败关闭。Linux 缺少 `bubblewrap` 或 `socat`
  时不允许以无沙箱方式退化运行。

## 非目标

- 不提供公开互联网注册，不把直连 CLI 定位为不可信租户的强隔离方案。
- 不支持多主机调度、多副本共享 SQLite、共享 Worktree 或无停机滚动升级。
- 不在网页中开放执行后端、全局密钥、系统权限或沙箱开关。
- 不替代代码审查、供应链扫描、生产发布审批或项目自己的测试体系。
- 不保证在 4U8G 上稳定运行 8 个以上 Agent；扩容优先升级主机或采用专用 Worker。

## 发布验收

- 现有契约测试和新增的 API、SQLite、文档、Runner、并发、前端与浏览器测试全部通过。
- Python 3.10/3.13、Node 22、Ruff、覆盖率和部署 smoke test 通过。
- Linux 实机沙箱无法读取另一租户 sentinel、服务环境文件或主密钥路径；任何成功读取都阻止
  发布，并要求另行设计并验证更强的隔离方案。
- 真实 Codex/Claude 并发 4 压测 30 分钟；若内存超过 80%、swap 持续增长、发生 OOM 或页面
  明显阻塞，部署配置降为全局并发 2。
- `git diff` 确认 FastResearch、FastNews 没有新增修改。

## 可复用 Agent

Agent 指能力定义；Codex/Claude 指执行器；规划/执行/验收指角色。
用户可以创建、修改、复制、归档定义，定义的指令和 Skills 随版本保存。
任务创建时固定角色定义和可用目录，Planner 可引用已有定义或生成任务内临时定义。
确认前允许重新分配或编辑临时定义，用户可另存入库；确认后由平台统一调度。
任务不自动继承后续定义变更，不自动沉淀跨任务记忆。操作细节见 [Agent 与协作](agents.md)。
