## 本轮目标

让每个 FastResearch 用户都能在自己的 FastLab 空间中配置：

1. Planner 使用 Codex 还是 Claude，以及对应模型；
2. Worker 的默认执行器和模型，同时保留任务确认页对子任务/验收器的逐项覆盖；
3. 自己的任务分发（orchestration）Skill；
4. 模型认证来源：Codex CLI、Claude CLI，或用户自己的 API Key；未提供 API Key 时默认使用 Codex CLI，并在网页用一句短说明明确告知；
5. 一个用户级大工作目录，并在其中创建仓库、任务文档、运行时和任务级小 Worktree。

- 托管仓库只提供“永久删除仓库”，同时删除登记和 `<repository-root>/<repository-id>/`；不再
  提供会遗留孤立目录的“仅移除记录”。外部 local 路径仍只能移除登记。
- 永久删除只适用于路径恰好为当前托管根目录直接子目录、目录名等于仓库 ID、且不是符号链接的
  仓库；显式 `--workspace` 等外部本机路径永远不能通过网页删除。
- 有未结束任务时拒绝永久删除。永久删除前要求明确确认，说明仓库文件、未推送提交和后续重跑
  能力都会丢失。
- 文件删除采用同一文件系统内的临时改名：先校验并暂存目录，再删除数据库记录；数据库失败则
  恢复目录，成功后递归清理暂存目录，减少记录与文件状态不一致。

验收：托管仓库只能永久删除；普通删除接口在托管模式被拒绝；路径越界、符号链接、ID/目录不匹配、
活动任务和 local 路径均被永久删除接口拒绝；删除数据库失败时目录恢复；页面需要明确二次确认并有自动化测试。

完成记录（2026-09-28）：仓库状态仅对路径严格匹配系统生成 ID 的目录返回 `deletable`；页面
据此显示永久删除按钮。删除流程先把目录原子改名到同文件系统暂存路径，再删除登记并清理目录；
登记删除失败会恢复原目录。测试覆盖活动任务、外部路径、数据库失败恢复、实际目录删除和确认后的
前端接口调用。

## 每项功能完成时的更新规则

每完成一个 P 项或其中可独立交付的子功能，必须在同一提交/工作批次中：

1. 把本文件对应状态改为 `✅ 已完成（YYYY-MM-DD）` 或写明剩余项，不允许只写“进行中”；
2. 在“当前完成度”中记录实际行为，不以设计稿或未合并代码作为完成依据；
3. 更新受影响的 `README.md`、`docs/requirements.md`、`docs/architecture.md`、`docs/configuration.md`、`docs/data-model.md`、`docs/api.md`、用户流程和故障排查文档；
4. 记录执行过的测试及未执行原因；涉及真实 CLI 的功能必须区分假 CLI 自动测试与服务器实机验证；
5. 最后分别检查 `git -C ../FastNews status --porcelain` 与
   `git -C ../FastResearch status --porcelain`，确认没有因 FastLab 工作产生新改动。

## 保持不变的边界

- 规划、执行和验收仍使用 Codex CLI 或 Claude CLI；不引入远程 Worker、消息队列或完整 Orca Runtime。

- 单主机、单 FastLab 服务进程、SQLite；不支持多个实例共享同一数据目录/Worktree。
- 不使用 tmux，不直接暴露 FastLab 端口，不恢复飞书入口。
