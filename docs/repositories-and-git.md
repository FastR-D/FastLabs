# 仓库、Worktree 与交付

## 登记仓库

FastLab 支持登记多个本机仓库，每个仓库使用一个别名。网页和飞书创建任务时都通过别名选择仓库；飞书不会显示本机绝对路径。

创建任务时还可以填写仓库内已存在的相对工作目录，例如 `web`。省略时表示整个仓库。FastLab 拒绝绝对路径、`..`、文件路径以及通过符号链接逃出仓库的目录。

Agent 可以读取完整仓库，但任务结束前会检查所有改动。如果修改、删除、重命名或新增了工作目录之外的文件，FastLab 不提交、不合并，并把任务转为需要处理。

## 非 Git 文件夹

登记非 Git 文件夹时，网页会先请求确认，不会静默初始化。确认后 FastLab 会：

1. 执行 `git init`。
2. 在本地排除 `.fastlab/`。
3. 遵守已有 `.gitignore`。
4. 把其余文件创建为 `Initial snapshot by FastLab` 初始提交。

已有 `.git` 但没有提交的仓库，可以在仓库列表点击“创建初始提交”。执行前应确认目录中没有密钥或其他不应进入 Git 的文件。

## Worktree 布局

用户不需要为并发任务复制文件夹。确认执行后，FastLab 自动把完整 Git Worktree 放在运行数据目录中：

```text
.fastlab/worktrees/<task-id>/
├── integration/
├── sub-01/
├── sub-02/
└── sub-03/
```

分支命名：

```text
fastlab/task-<short-id>-integration
fastlab/task-<short-id>-sub-01
fastlab/task-<short-id>-sub-02
```

每个子任务在独立进程、分支和 Worktree 中运行。完成后先提交自己的分支，再按顺序合入集成分支。合并冲突会立即中止合并并保留现场，不修改目标分支。

## 安全交付

最终验收通过后，FastLab 按以下规则把结果交付到目标目录：

- 目标目录没有未提交改动。
- 目标目录仍位于任务开始时的分支。
- 目标分支没有新提交时，直接安全快进到集成结果。
- 目标分支有用户新提交时，先在隔离的集成 Worktree 中合入这些提交，不修改目标目录。
- 同步无冲突后自动重新验收；只有新组合通过验收，才快进目标分支。
- 同步发生冲突或目标分支历史被改写时停止交付，保留现场供处理。

任何检查失败都不会覆盖用户文件，任务会转为“需要处理”。用户可以先提交目标目录中的正常修改，再点击“应用结果”；FastLab 会同步并重新验收，而不是要求删除这些提交。

## 清理策略

- 成功验收并交付：自动删除临时 Worktree 和当前任务的 `fastlab/task-<short-id>-*` 分支。
- 停止、失败或尚未交付：暂时保留现场，方便重试、追加说明和排查。
- 手动“清理临时数据”：删除该任务的 Worktree 和精确记录的任务分支。
- 删除任务：同时删除数据库记录、日志、文档、Worktree 和任务分支。

清理后不能再用“追加说明”恢复旧 Agent 会话；已交付任务应使用“继续修改”，从目标分支当前 HEAD 创建新任务。

FastLab 不使用通配符批量删除分支，只处理数据库中属于当前任务且符合任务前缀的精确分支，不会删除用户创建的其他分支。
