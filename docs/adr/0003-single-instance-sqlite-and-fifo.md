# ADR-0003：单实例 SQLite 与分层 FIFO 并发

- 状态：已接受
- 日期：2026-09-25

## 背景

目标主机为 4U8G，约 50 人需要同时浏览和提交，但 Agent CLI 的 CPU/内存远高于控制面。当前
数据位于本地 SQLite、Git 仓库和 Worktree，跨实例协调会引入分布式锁、队列和共享文件系统。

## 决策

部署一个 FastLab 进程，SQLite 使用 WAL 和短事务。所有 Planner、Worker、Verifier 共用全局
FIFO 门，默认全局 4、每用户 1；任务自身并发再取更小值。50 名用户可以排队，不承诺 50 个
Agent 同时运行。

若 30 分钟真实并发 4 压测出现内存超过 80%、swap 持续增长、OOM 或控制面阻塞，部署值降为
2。需要稳定 8 个以上 Agent 时先升级主机或设计独立 Worker，不通过多开 Web 进程绕过。

## 后果

- 实现简单，可保持现有 SQLite 和 Worktree 行为。
- FIFO 与每用户限制降低饥饿和单租户占满风险。
- 服务和主机构成单点，依赖每日备份与 4 小时恢复目标。
- 不支持多副本、无停机滚动部署或 NFS 上共享数据。
